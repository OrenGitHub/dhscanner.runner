# 2x2 grid POST endpoint enumeration on formbricks v3.16.0
#
# Expected output of the swipl query in the "assert 2x2 grid POST endpoint
# enumeration on formbricks KB" CI step. Two predicates in play, both defined
# in dhscanner.service.queryengine/utils.pl :
#
#   1. utils_unauthenticated_http_post_handler_request_object/3
#      -> POST handlers whose bodies do NOT reach a recognized auth check.
#      Prefix : "UNAUTH: "
#
#   2. utils_authenticated_http_post_handler_request_object/5
#      -> POST handlers whose bodies reach a recognized auth check.
#      Prefix : "AUTH:   ", plus the auth-function name and the AuthEvidence
#      tag ( currently either by_header_null_check(K) or by_all_but_one_bad_return ).
#
# 20 total POST handlers today ( 18 pre-auth + 2 auth ).
#
# Lines are sorted alphabetically by URL ( Prolog sort/2 semantics ) so the diff
# against `actual` is order-stable. Lines starting with '#' and blank lines
# are stripped by the CI checker before comparison.
#
# Precision / recall context ( see docs/AUTH_POST_RECALL_GAPS.md ) :
#   - AUTH bucket    : 100% precision, ~10% recall on the true set
#     ( ~20+ authenticated POSTs in ground truth ; misses are dominated by
#     the authenticatedApiClient HOC-wrapper pattern that we don't unroll ).
#   - UNAUTH bucket  : ~44% precision -- ~10 of the 18 are actually
#     authenticated but the auth lives one hop away ( HOC wrapper,
#     inline secret-compare, delegated verifier ). These are HONEST
#     misses of the recognizer, snapshotted here so future recall
#     work can measure its own delta.
#
# If this snapshot changes, DELIBERATE audit is required :
#   - Additions   : verify the new endpoint is real ( did formbricks add a route ? )
#                   or that the recognizer widening was intentional.
#   - Removals    : verify the missing endpoint is genuinely gone
#                   ( not a regression in the recognizer ).
#   - AUTH edits  : verify the auth-function name + AuthEvidence tag are correct.
